# Технический аудит — рабочий контракт 0.2.1

## Назначение и границы

Оценить публичное техническое состояние сайта и дать разработчику проверяемый пакет действий. Не обещать рост трафика, конверсии или денег по одному техническому измерению. Сайт с авторизацией оценивается в доступном публичном слое; приватные функции требуют отдельно предоставленного доступа и scope.

Источник примера: [пакет Paper Planes 11.10.2026](https://drive.google.com/drive/folders/10Hj0if35_ZoLKLrRWMoyJ0sYHsx6zqge). В нём 205 пунктов и 87 задач конкретного среза, исходники сборщиков исключены. Настоящие сборщики написаны заново. Этот каталог не заявляет восстановление всех 205 правил или инструментов автора. Числа, адреса, CMS и даты примера не являются универсальными требованиями.

До сбора указать решение, профиль, хост/стартовый URL, лимиты запросов/адресов, права источников, папку результата и downstream-владельца. Реестр проверок и evidence trace получают гейты scope/non-duplication/traceability/coverage. Применять общий стандарт структурных артефактов из AGENTS при создании соответствующих структур; не превращать весь аудит в issue tree автоматически.

HTTP-сборщик выполняет GET одного хоста, не отправляет формы, не авторизуется и не изменяет сайт. Браузер запускается в новом контексте, не использует cookies пользователя; блокирует POST/PUT/DELETE и WebSocket, если API доступен. Обычная загрузка страницы может запускать публичную аналитику. Не нажимать CTA, не оформлять заказ и не создавать лид без отдельной команды. Robots, ограничения ресурса и разрешённый scope сохраняются.

Не скачивать и не проверять внешний хост вслед за редиректом без расширения scope. HTTP-коллектор сохраняет такой переход как незавершённую проверку. Браузер может загружать публичные сторонние ресурсы, необходимые странице; переход документов ограничен исходным хостом и сохранёнными robots. Умеренная частота: HTTP по умолчанию 0,5 секунды между запросами с учётом crawl-delay/request-rate. Robots 401/403/5xx, ошибка получения или усечение → доступ не подтверждён, обход не продолжается.

## Профили

| API-идентификатор | Значение | Дополнительный ручной/агентский слой |
|---|---|---|
| `corporate` | Корпоративный сайт | Услуги, кейсы, контакты, эксперты, claims, переходы материалов к услугам |
| `store` | Интернет-магазин | Каталог/товар, варианты, фильтры, параметры, пагинация, видимые цены/условия, Product/Offer; заказ не исполнять |
| `media` | Медиа / база материалов | Авторы, рубрики, архивы, даты, пагинация и связи статей |
| `app` | Веб-приложение | Публичные маршруты и HTML/DOM; приватные состояния и authenticated API вне автоматического сбора |

Общий сбор одинаков; профиль задаёт обязательный предметный review. Функции магазина/приложения не объявлять проверенными только потому, что их профиль выбран.

## Команды

Python 3.9+; HTTP-коллектор использует только стандартную библиотеку. --workers 1–32 сохраняет общий интервал и бюджет; --seed-file принимает ограниченный JSON-массив приоритетных URL того же хоста. --resume продолжает тот же срез с прежним хостом/правами и накопленным счётчиком, заново проверяя robots. Playwright и браузер нужны только для второго этапа. Автоматической установки зависимостей нет. В Codex пути Node/Python/пакетов получить через `load_workspace_dependencies`; в другом окружении использовать его установленный runtime. Не зашивать путь одного компьютера в переносимую команду.

```sh
AUDIT_SKILL="$HOME/.codex/skills/bpm6-website-positioning-audit"
python3 "$AUDIT_SKILL/scripts/audit_site.py" https://example.com/ \
  --out '/существующий/проект/Аудит example.com 2026-10-11' \
  --profile corporate --max-pages 200 --max-requests 500
```

Каталог среза должен быть новым. Лимиты по умолчанию: 200 адресов, 500 HTTP-запросов, глубина 8, 10 sitemap-документов, 5000 loc, 50 уникальных внутренних CSS/JS, 300 img src, 3 HTML URL прямых HTTP-серий, 4 потока, 2 МиБ на ответ, timeout 15 секунд. Общий лимит запросов действует на страницы, ресурсы, изображения и пробы; частота общая для всех потоков. Параметрические URL только с `--include-query` после решения о scope; иначе они видны как исключённые. `--allow-local` разрешает loopback только для явно разрешённых локальных тестов.

HTTP-редиректы сохраняются по каждому переходу. Тела ответов хранятся отдельно; усечённый ответ не считается полным evidence. Внешние ссылки, private/non-public hosts и закрытые URL не обходятся автоматически. Несогласованный конечный адрес, request limit и robots имеют явную причину в raw.

```sh
# Если Playwright уже установлен: указать каталог пакетов через NODE_PATH.
node "$AUDIT_SKILL/scripts/browser_probe.cjs" \
  --audit '/существующий/проект/Аудит example.com 2026-10-11' \
  --urls 'https://example.com/,https://example.com/services/' \
  --widths 360,412,1365 --repeats 3 --window 5000

# Пересборка отчёта из raw; сетевые запросы отсутствуют.
python3 "$AUDIT_SKILL/scripts/audit_site.py" \
  --out '/существующий/проект/Аудит example.com 2026-10-11' --render-only
```

При необходимости `--chrome <путь>` / `AUDIT_CHROME` указывает существующий Chrome. `AUDIT_PYTHON` выбирает Python для проверки robots. По умолчанию браузер выбирает до трёх представителей первых сегментов URL; это эвристика, не доказательство покрытия всех шаблонов. Лучше явно выбрать главную, приоритетную услугу/товар, статью и проблемный адрес. Max pages браузера задаётся отдельно, максимум 20. Повторная запись browser.json запрещена: для новой серии нужен новый срез.

Браузер собирает конечный URL, документы и ответы ресурсов, requestfailed, DOM, H1, изображения, горизонтальное переполнение, геометрию крупных fixed/sticky-блоков и снимок первого экрана. Крупный блок — кандидат на ручную проверку перекрытия; наличие размера во внешнем CSS может опровергнуть HTML-кандидат отсутствия width/height. Query-scope проверяется на каждом переходе документа; query версионированных ресурсов не исключает ресурс автоматически. Robots применяется ко всем внутренним запросам, не только к документам; причины блокировки сохраняются в scope_blocked. Адреса проверяются стандартным Python ipaddress, включая IPv4-mapped IPv6; loopback разрешён только явным тестовым флагом.

Наблюдаемые LCP/FCP/CLS/TTFB — лабораторные значения за фиксированное окно. По умолчанию нет искусственного ограничения сети/CPU; viewport не равен эмуляции медленной мобильной сети. Browser-summary даёт медиану только при минимум трёх чистых 200-загрузках с неизменным URL и одинаковым профилем, без реальных сетевых ошибок, с dom_usable и speed_clean, без профилирования/блокировок/превышений лимита. Отсутствие пригодной серии не становится положительным вердиктом. CLS считается по окнам layout shift; взаимодействие/долгая прокрутка не тестируются. Long tasks сохраняются, но не называются Lighthouse TBT. INP не рассчитывается. DNS/robots guard и request routing вносят инструментальную задержку: эти показатели являются диагностическими, а приёмка скорости требует отдельного сопоставимого инструмента/профиля с известной инструментальной нагрузкой. Не выдавать чистоту сети за доказательство отсутствия этой задержки. Полевые Core Web Vitals требуют датированных данных реальных пользователей.


### Продолжение и отдельное профилирование

Для незавершённого среза разрешён --resume с прежним URL/правами и накопленным бюджетом. Он продолжает неохваченные адреса; адресный повтор ошибок сохраняется отдельно и не подменяет исходные наблюдения. Полный новый аудит использует новый каталог.

Отдельная серия покрытия кода в том же каталоге:

~~~sh
node "$AUDIT_SKILL/scripts/browser_probe.cjs" \
  --audit '/существующий/проект/Аудит example.com 2026-10-14' \
  --urls 'https://example.com/,https://example.com/services/' \
  --widths 1365 --repeats 3 --window 5000 \
  --coverage yes --output-name browser.coverage.json
~~~

--max-resources, --max-transfer-bytes, --max-dom-elements, --max-links и --coverage-max-bytes ограничивают браузерный сбор. При достижении лимита соответствующий слой сохраняет остаток/нижнюю границу. Имена новых серий должны оставаться внутри raw; повторное перезаписывание существующей серии запрещено. Профилирование не смешивается со скоростными медианами обычной серии.


## Каталог публичных проверок 0.2.1

HTTP/HTML: конечные ошибки и цепочки, soft-404-кандидаты, robots-группы и доступ указанных роботов, sitemap/noindex/canonical и повторные loc, кратчайшая навигационная глубина от стартовой страницы, входящие ссылки, пустые href/типовые анкоры и фрагменты. Title берётся из head; сохраняются H1–H6, повторные meta/canonical, viewport и длина description. Извлечение содержания имеет метод и ограничения: main/article либо body без очевидной навигации, подвала, SVG, форм и скрытых блоков.

Тексты: точные и близкие дубли, доля уникальных пятисловных шинглов, повторяющиеся блоки. Это кандидаты по объявленному корпусу и ограниченной выборке, а не доказанная SEO-неэффективность. Сопоставимость разных экстракторов проверяется отдельно. Ориентиры конфигурируются: --near-threshold 0.8, --unique-share-threshold 0.4, --repeated-block-words 50, --navigation-depth-threshold 4. Сохранять принятые значения и остаток сравнения.

Разметка: синтаксис JSON-LD, инвентарь типов, минимальные локальные профили Product/Service/Article/Organization/BreadcrumbList, типы значений, даты, Offer/цены, FAQ и AggregateRating. Это ограниченный набор предметных кандидатов, не полный валидатор schema.org и не решение Google о расширенном результате. Текстовая цена допустима в schema.org; требования поискового профиля проверяются отдельно. Отсутствие необязательного SearchAction не становится ошибкой.

Ресурсы: ограниченная HTTP-выборка внутренних img src с кодом, MIME, весом и кеш-заголовками; размеры и адаптивность по DOM, fetchpriority и LCP; head CSS/синхронные JS как кандидаты блокировки; font-display по выбранным CSS. Изображения srcset/CSS-фоны/внешние хосты не получают автоматически полную HTTP-проверку. Вес усечённого файла — нижняя граница, не полный размер.

Браузер: основная навигация и попытка заблокированного перехода, независимая пригодность DOM, переполнение/фиксированные блоки, source/DOM Title/canonical/robots, DOM-only ссылки и фрагменты, видимые малые цели касания, взвешенный размер текста, ширина Title в модели 20px Arial. Это диагностическая модель, не фактическая ширина поискового сниппета.

Сеть и скорость: CDP записывает ответы, заголовки, protocol и переданные байты с полнотой/нижней границей. Прямые серии HTTP используют три сопоставимых GET с gzip, затем условный GET при валидаторе. TTFB включает соединение/TLS/сервер, но исключает предварительные DNS/robots guard и очередь. Условный 200 может быть законным обновлением, а отсутствие gzip в пробе — кандидат; причинный диагноз не создаётся.

JS/CSS coverage собирается отдельной профилируемой серией. Счётчики относятся к исходным UTF-16 единицам, а не сетевым байтам; интервалы не суммируются повторно, injected scripts исключаются. Покрытие сценария не доказывает, что неисполненный код безопасно удалить. Профилирование исключается из скоростной приёмки.

Не реализованы автоматически: полный официальный семантический валидатор и все свойства schema.org, внешние HTTP-ссылки, полный сценарный аудит форм/клавиатуры/контраста, обязательность и достоверность бизнес-данных, полевые показатели, фактическая индексация, серверный profiling и коммерческая конверсия. Эти проверки получают отдельный предметный/доступный гейт; отсутствие измерения не означает «пройдено».

## Evidence и результат

`raw/manifest.json`: дата, version, профиль, конфигурация, robots, sitemap, полнота, остаток и ограничения. `raw/pages.json` и `raw/resources.json`: HTTP-коды, цепочки, заголовки, raw-файл, исходный HTML-анализ. `raw/browser.json`: повтор/профиль, текущий и конечный URL, попытки перехода, независимые признаки навигации/DOM/скорости, сеть, DOM, показатели, screenshot. Дополнительные raw: images.json, http-probes.json, content-analysis.json, jsonld-inventory.json, robots-policies.json и checkpoint.json. Профилирование — отдельный browser.coverage.json.

`report/checks.json`: системные поля `check_id` (код проверки), `title` (название), `status` (русский результат), `count` (число адресных строк), `confidence` (уверенность), `note` (границы), `action` (действие), `acceptance` (приёмка), `evidence` (физическая трасса), `next_check` (следующая проверка). Методы и внешняя документация не входят в фактический evidence.

`report/details.csv`: проверка, адрес/исходная страница/цель, фрагмент, физический файл, локатор, класс/права источника, статус evidence, уверенность, следующий check. Source-backed register строится до возможного причинного графа. Один crawl является одним измерительным срезом, не несколькими независимыми подтверждениями.

`report/tasks.json`, `report/ТЗ разработчику.md` и `Контроль исправлений.csv`: кандидаты по проверкам с действием и приёмкой. Главный агент после review объединяет связанные проверки одной причины/компонента, сохраняя все check_id и адресные строки. Сборщик сам не доказывает корневую причину; одна задача по LINK-01 агрегирует повторяющиеся ссылки, но HTTP-01 и LINK-01 могут требовать одного общего инженерного исправления. Персональные исполнители/сроки не выдумываются.

`report/Резюме владельцу.md`, `НАЧАТЬ ЗДЕСЬ.md`, `MANIFEST.sha256`: чтение, ограничения и целостность. CSV — формат первой версии; XLSX формируется только при запросе через соответствующий spreadsheet skill. Скрипт не объявляет Excel созданным.

`--render-only` обновляет генерируемый report и checksum, сохраняет raw и ручные поля контроля: состояние, исполнитель, версия, дата, доказательства; строки исчезнувших кандидатов не удаляются автоматически. Редакторские изменения generated report требуют отдельной посадки/синтеза, иначе последующая генерация заменит их. Новый публичный релиз → новый срез, не перезапись исходного.

## Агентские роли

Делегирование необязательно. При крупном сайте основной агент даёт компактные задания со ссылками на физические raw, без старых диалогов и технических дампов.

1. **Обход и индексация**: один сборщик; агент проверяет HTTP/robots/граф/sitemap, охват и адресные расхождения. Выход — проверка, source trace, факт/гипотеза, остаток.
2. **Шаблоны и содержание**: читает тот же raw, выбирает представителей шаблонов, проверяет назначение, метаданные, дубли/разметку и claims. Не запускает второй полный обход. Выход — адресная дельта и решения редактора/владельца.
3. **Браузер и скорость**: выбранные URL и профили, полные повторы, чистота сети, совпадение URL, визуальный review. Выход — реальные измерения, ограничения и запросы повторов.
4. **Независимый reviewer**: не принимает авторские выводы как evidence; открывает физические файлы, проверяет сильные claims, ложные pass, счётчики и приёмку. Выход — предметные ошибки и verdict по объявленному scope.

Главный агент сверяет актуальные файлы перед интеграцией, исправляет найденные расхождения, разделяет факты/интерпретации/действия и выпускает один пакет. Не считать результат клиента внедрённым, принятым или эффективным по одному созданному отчёту. ClickUp и публикация не входят в разрешение на аудит.

## Проверки доказательности после обновления 14.10.2026

Ошибки версии 0.1.0 (SVG в Title, пустое main_text на Tilda, iframe вместо основного документа, положительный вердикт при пустой пригодной выборке) исправлены и сохраняются как регрессионные случаи в scripts/test_audit.py. Новый audit остаётся экспериментальным: исправленный тест не доказывает полное покрытие всех сайтов.

- navigation_ok, dom_usable и speed_clean — разные признаки. Заблокированная аналитика/iframe хранится как инструментальное вмешательство; пригодный DOM сохраняется, а влияние guard не скрывается в скорости. Внутренний chrome-error:// не считается загруженной публичной целью. Основная попытка перехода остаётся отдельным наблюдением.
- Нулевое число переходов не даёт положительного вердикта, если часть основных навигаций не измерена или заблокирована границами сбора. Указывать пригодную выборку и непокрытый остаток; блокировку iframe/POST учитывать отдельно от основного документа. Неудачное браузерное наблюдение само по себе не доказывает сетевой дефект сайта.
- Для fragment-ссылок сначала искать точный ID в исходном HTML/DOM. Если его нет, известные команды submenu:/popup:/служебный префикс сохранять как отдельный кандидат сценарной проверки интерфейса: это не отсутствующий обычный якорь и не доказательство работы команды. Обычный отсутствующий #id сохраняет проверку сломанного якоря.
- Автоматически отменённый пустой favicon исключается из скоростного запрета только по узкому условию; остальные реальные ошибки ресурса и ограничения сохраняют запрет. Неполные CDP-байты остаются нижней границей.
- Сравнивать одинаковые терминальные URL, предварительно установив смысл status у обоих сборщиков. Наличие href подтверждает ссылку; конечный HTTP-дефект требует отдельного ответа/цепочки.
- Строки «проверка × URL», страницы, пары ссылок и конечные адреса не суммировать как одинаковые единицы. Query-варианты одного пути ресурса не называть разными файлами.
- Осознанные robots/query/byte-ограничения не исправляются повтором с тем же лимитом. Тайм-ауты допускают адресный повтор с отдельным следом; --resume продолжает незавершённую очередь, но автоматически не переписывает старые ошибки.
- Сохранять исходный срез; новый код может пересобрать выводы из старого raw, но отсутствующие новые поля остаются неизмеренными. Новую публичную проверку подтверждает только свежий сбор, а не изменённый отчёт.
- Для Python-файлов с длинными русскими строками сохранять явный UTF-8 coding header: локальный Python 3.9.6 ошибался в прямом CLI при корректных байтах и успешном py_compile. Проверять фактический CLI, а не только компиляцию.
- Checkpoint JSON и замены исполняемого кода записывать атомарно через временный файл и replace. Читатели не должны видеть частичный JSON/UTF-8.
- Исправление длины description не подтверждает SEO-эффект, индексацию или приёмку разработки.

Коррекция браузерного компонента 0.2.1: размер CSS coverage берётся из CSSStyleSheetHeader.length, а не из веса содержащего HTML. Изменение CSS после сохранённого заголовка делает слой неполным. Идентичность PNG включает имя серии, поэтому новая серия не перезаписывает прежние снимки. Если для анализа выбрана нестандартная серия, manifest.browser_coverage_file явно указывает её относительный JSON внутри raw; путь вне raw отклоняется. [Первичная схема CDP CSS](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/pdl/domains/CSS.pdl).

Коррекция браузерного компонента 0.2.2: популяция JS/CSS coverage определяется идентичностью главного CDP-фрейма и execution context. Принадлежность URL хосту не заменяет эту идентичность: внешний script главного документа может быть релевантен, а внутренний error-CSS iframe не относится к его покрытию. Дочерние фреймы и внутренние URL исключаются с причиной; неизвестная identity сохраняет частичный статус. Пригодный DOM родителя не доказывает чистоту покрытия его дочерних фреймов. Старые серии сохраняются, исправленный фильтр подтверждается отдельным свежим сбором.
Итог profiling показывает пригодные прогоны относительно всей серии. Тайм-ауты, непригодные DOM и заблокированные основные навигации входят в реестр пробелов, даже когда другие прогоны дали полноценное измерение. Скрывать их фильтром пригодности запрещено.

HTML-viewport сохраняет width/initial-scale/запреты масштабирования как диагностические кандидаты. Для старого ориентира «не менее 60% видимого текста от 12px» малый текст оценивается по доле символов; --small-font-share-threshold 0.4 допускает явное изменение порога. Бюджет изображений 800 KiB относится к сумме измеренных изображений профиля, с отдельной полнотой/нижней границей, а не только к одному файлу.
