# Печать A4 из HTML — Paper Planes (HTML → A4 PDF)

Ты превращаешь HTML в печатный A4-PDF и (для гайдбуков) публикуешь по ссылке.
Движок один — Chrome headless + `@media print` CSS. Профиля два:

- **Профиль А — blueprint-методичка с вкладками.** Фирстиль Балахнина, вкладки,
  таймлайн, глоссарий, «1 вкладка = 1 страница». Стиль — `assets/print-blueprint.css`,
  скелет — `assets/template-blueprint.html`. Эталон: методичка «Админ рабочей группы»
  (`2026/Найм и адаптация/Админ_роль_методичка.html`).
- **Профиль Б — произвольная HTML-вёрстка.** Чужой лендинг, отчёт, статья без вкладок
  и без фирстиля. Стиль — `assets/print-generic.css` (универсальные правила A4,
  ни к каким классам не привязаны).

`scripts/make_pdf.sh` формат-независимый — рендерит любой HTML обоими профилями.

## Когда использовать

ВЫЗЫВАЙ скилл, если:
- просят «версию для печати», «PDF под A4», «распечатать эту страницу / документ»;
- жалуются «PDF косой / не печатается / разделы разъезжаются / съезжает вёрстка»;
- просят «сделать методичку / гайдбук» с разделами и вкладками (→ профиль А);
- просят «опубликовать как bk-guide / azbuka-guide» (поддомен `<name>-guide.paper-planes.ru`, → профиль А);
- хотят «каждая вкладка — одна страница» (→ профиль А).

Не уверен, какой профиль — спроси: «фирстиль с вкладками или обычная страница?».
Признак профиля А: есть `nav.tabs`/`section.tab` и палитра blueprint. Иначе — профиль Б.

НЕ вызывай для:
- консалтинговых слайдов PPTX (это `consulting-slides-creator` / `pp-slidument`);
- клиентских кейсов на сайт (это `pp-case-writing`);
- постов и каруселей в соцсети (это `ii-channel-cover` / blueprint через PIL);
- Word / Google Docs / PPTX в PDF — это не HTML, печатай экспортом из самого редактора.

Если HTML/PDF/PNG proposal artifact сначала нужно сделать редактируемым, восстановить baked text, разметить `data-field` или починить template reconstruction, это не задача `pp-print-a4`: сначала можно вызвать derivative subskill `html-proposal-template-editor` из `~/.codex/derivative-subskills/html-proposal-template-editor/`, а сюда возвращаться только для финального A4/PDF print layer.

## Профиль Б — произвольный HTML (быстрый путь)

1. Вставь `assets/print-generic.css` в конец `<style>` страницы (или подключи
   `<link rel="stylesheet" media="print" href="print-generic.css">`). Если править
   исходник нельзя — сделай копию HTML и впиши блок туда.
2. Сгенерь PDF: `bash scripts/make_pdf.sh "стр.html" "стр_печать.pdf"`.
3. Проверь первую страницу через `sips` (см. ниже).

Что делает `print-generic.css`: A4 portrait, поля 12mm, `print-color-adjust: exact`,
убирает фиксированные фоны (косят PDF), прячет навигацию/кнопки/формы/видео
(и всё с классом `.no-print`), распускает `position: fixed/sticky` в поток,
не рвёт по середине таблицы/картинки/блоки, многоколоночные сетки сводит в одну
колонку, картинки масштабирует по ширине. Утилиты: `.page-break` (новая страница),
`.avoid-break` (не разрывать), `.print-2col` (две колонки), `.no-print` (скрыть).

## Профиль А — blueprint-методичка (алгоритм)

### 1. HTML-структура (если делаешь с нуля)

Эталон — `assets/template-blueprint.html` (скелет blueprint с вкладками). Ключевое:
- Палитра: `--paper #F8F5ED`, `--ink #1A1A1A`, `--red #E84A38`, `--bg-block #F0EDE3`.
- Шрифты Google Fonts: Oswald (заголовки), Inter Tight (текст), JetBrains Mono (мета/код), Unbounded (акценты).
- Координатная сетка фоном (`background-image` из двух linear-gradient 24px).
- Вкладки через vanilla JS (`nav.tabs button[data-tab]` → `section.tab`).
- Глоссарий отдельной вкладкой; термины в тексте — `<a class="term" data-glossary-id="g-...">` с переходом на определение.
- Машинный слой: JSON-LD (`schema.org/TechArticle` + `DefinedTermSet`), `<meta name="description">`, `<abbr title>`.

### 2. @media print — ГЛАВНОЕ

Возьми готовый блок `assets/print-blueprint.css` и вставь в `<style>` HTML. Он решает грабли,
на которые мы напоролись:

| Грабля | Решение в print-blueprint.css |
|---|---|
| `background-attachment: fixed` сетка косит PDF | `background-image: none !important` для печати |
| grid в 4 колонки обрезается по ширине A4 | `grid-template-columns: 1fr 1fr` (2 колонки) |
| таймлайн дня (18 слотов) на 2 страницы | `column-count: 2` + `slot::before { display:none }` + border-left |
| глоссарий (30+ терминов) разливается | `column-count: 2`, термин+определение `break-inside: avoid` |
| карточки/строки рвутся посередине | `page-break-inside: avoid` на `.card`, `tr`, `.slot`, `.day` |
| фоны карточек не печатаются | `-webkit-print-color-adjust: exact !important` |
| вкладки наслаиваются | `section.tab { display: block !important; page-break-before: always }` |
| «1 вкладка = 1 страница» | `page-break-before: always` + `page-break-after: always` на `section.tab` |

Размеры под A4: `@page { size: A4 portrait; margin: 9mm }`, базовый шрифт `8pt`,
`line-height 1.25`. Это даёт ~12 страниц на 9 вкладок (плотные таблицы-вкладки
занимают 2). Дожать до строго 1:1 можно ~6.5pt, но на бумаге нечитаемо — по умолчанию
НЕ дожимай, спроси пользователя.

### 3. Генерация PDF

```bash
bash scripts/make_pdf.sh "путь/к/methodika.html" "путь/к/methodika_печать.pdf"
```

Скрипт зовёт Chrome headless с правильными флагами
(`--print-to-pdf-no-header --no-pdf-header-footer --virtual-time-budget=8000`)
и считает число страниц. `virtual-time-budget` нужен чтобы Google Fonts успели
загрузиться (требуется интернет при рендере).

### 4. Визуальная проверка

```bash
sips -s format png "methodika_печать.pdf" --out /tmp/check.png   # рендерит 1-ю страницу
```
Открой через Read — убедись что не косит, карточки в 2 колонки, ничего не обрезано.
`sips` берёт только первую страницу; для остальных полагайся на счётчик страниц и CSS.

### 5. Публикация (по схеме bk-guide)

На PPM-VPS (`ssh ppm-vps`) гайды лежат в `/var/www/<name>-guide/`, Caddy раздаёт
по `<name>-guide.paper-planes.ru` + fallback `<name>-guide.72-56-234-191.sslip.io`
(sslip обходит DNS, работает сразу).

```bash
ssh ppm-vps "mkdir -p /var/www/NAME-guide"
scp methodika.html ppm-vps:/var/www/NAME-guide/index.html
scp methodika_печать.pdf ppm-vps:/var/www/NAME-guide/NAME-guide-print.pdf
# добавить Caddy-блок (см. assets/caddy-block.txt), потом:
ssh ppm-vps "caddy validate --config /etc/caddy/Caddyfile && systemctl reload caddy"
```

Caddy-блок копируй из существующего `bk-guide` (см. `assets/caddy-block.txt`).
Для красивого домена `<name>-guide.paper-planes.ru` нужна A-запись
`NAME-guide → 72.56.234.191` в DNS-панели paper-planes.ru — это ручной шаг
пользователя. sslip-версия работает без DNS.

## Грабли инфраструктуры

- **Прямо названный фирменный стиль:** до вёрстки открыть актуальный первичный визуальный референс бренда и проверить логотип, шрифты, палитру и композицию. Для такого документа использовать профиль Б с фирменной вёрсткой; профиль А применим к явно выбранному blueprint-стилю. Сохранять содержательный исходник и итоговый PDF в существующем контуре материала в Vault / Drive; в автономную HTML-версию встраивать шрифты и логотип. После сборки сверять сохранность текста с исходником и просматривать рендер всех страниц самого PDF.

- **Названия методологических элементов:** на обложке, в схемах и кратких расшифровках сохранять названия из действующей программы и методического источника. Не подменять тип вопроса его темой или результатом (например, «извлекающие вопросы» словом «последствия»); смысловое пояснение давать отдельно.

- **Рабочие тетради с полями:** пустые строки Markdown вида `1.` / `-` преобразовывать в реальные поля с достаточной высотой для записи. Заголовок рабочего листа, короткую инструкцию и первую строку таблицы держать вместе; при переносе таблицы повторять её шапку. Глоссарий переносить парами «термин + определение», не целым неразрывным блоком.
- **Измерение страниц и шрифты:** до автоматической пагинации явно загрузить используемые веса шрифтов через `document.fonts.load` с образцом кириллицы, затем дождаться `document.fonts.ready`. Одного ожидания до появления текста недостаточно: оно может завершиться до запроса нужного поднабора. Для автономного HTML встраивать шрифты. У контейнера фиксированных A4-листов сбрасывать унаследованные внешние отступы, включая `main`; после рендера проверять отсутствие страниц только с колонтитулом.
- **Счётчик после пересборки PDF:** `mdls` может вернуть старое число страниц из Spotlight. Итоговый объём подтверждать прямым чтением актуального PDF через `pdfinfo`, `pypdf` или `pdfplumber`; при расхождении не повторять число из кэша.
- **Фиксированные A4-листы с колонками:** при `height` у листа и `break-inside: avoid` у вложенных блоков содержимое может перейти на следующую физическую страницу поверх её шапки, сохранив ожидаемое общее число страниц. После загрузки шрифтов измерять низ блоков относительно начала нижнего колонтитула; при выходе перераспределять целые вопросы/карточки между листами. После печати отдельно проверять шапки всех страниц и полный постраничный рендер; не скрывать выход через `overflow: hidden`.

- **Переносимые имена PDF и ZIP:** перед передачей проверять имена итоговых файлов и всех записей архива на символы, запрещённые в Windows: `< > : " / \ | ? *`, управляющие символы, а также конечные пробелы и точки. Двоеточия в названиях материалов заменять тире в имени файла; видимый заголовок документа сохранять. После пересборки ZIP проверять целостность, точный состав и побайтное совпадение вложений с актуальными PDF. Успешное открытие архива на macOS не подтверждает переносимость его имён.

- **Матрицы девяти действий и другие таблицы на 12+ колонок:** не ужимать исходную
  матрицу до нечитаемого кегля. Для A4 landscape вынести реестр актантов на отдельный
  лист, а матрицу разложить на три представления с одинаковыми идентифицирующими
  колонками и тройками действий: `Stabilise / Monitor / Trigger`,
  `Destroy / Shift / Conditional`, `Create / Request / Interaction`. Перед печатью
  проверить, что во всех трёх представлениях сохранено одинаковое число исходных строк
  и что ни один problem node не потерян.

<!-- agents-norm:С-149:start -->
12. **Именование папок и файлов — по-русски, с заглавной буквы.** Длинное тире `—` в составных именах. Легаси-нижний-регистр-с-дефисами не плодить.
<!-- agents-norm:С-149:end -->

### С-150. Цветовое кодирование пилларов

<!-- agents-norm:С-150:start -->
13. **Формат дат.** В текстах: `ДД/ММ/ГГГГ` (слэш). В именах файлов: `ДД-ММ-ГГГГ` (дефис).
<!-- agents-norm:С-150:end -->

### С-151. Цветовое кодирование пилларов

<!-- agents-norm:С-151:start -->
14. **Wikilink-разметка обязательна.** При написании текста в `Vault/*.md` известные сущности словаря `Vault/90-инфра/_Словарь-wikilink.json` сразу оборачиваю в `[[wikilink]]` (первое вхождение на канон; персоны с qualifier; alias через pipe). Хук `wikilink-enforce.py` страхует, но не замещает: L1 — моя дисциплина, L2 — хук. Детали: `.Codex/rules/06-wikilink-discipline.md`.
<!-- agents-norm:С-151:end -->

### С-152. Цветовое кодирование пилларов

<!-- agents-norm:С-152:start -->
15. **Obsidian-safe Markdown и теги.** При правке `Vault/*.md` проверять не только YAML-парсинг, но и Obsidian-читаемость. В frontmatter теги писать только как многострочный `tags:` без `#`, без flow-списков и без wikilink-ов; внутренние ссылки в теле Vault-файлов писать как `[[wikilink]]` или `[[wikilink|alias]]`, а не как markdown-ссылки на абсолютные пути, `file://`, URL-encoded пути или ссылки с `%20`. Абсолютные markdown-ссылки допустимы в ответе чата для кликабельности, но не как внутренняя разметка Vault-документа. После правки файлов с frontmatter, tags, wikilink-ами, таблицами или реестрами запускать targeted search на `file://`, `/Users/`, `%20`, markdown-ссылки на локальные Vault-пути и `#`-теги во frontmatter; YAML OK сам по себе не считается достаточной проверкой.
<!-- agents-norm:С-152:end -->

### С-153. Цветовое кодирование пилларов

<!-- agents-norm:С-153:start -->
16. **Имена и актуальный статус сотрудников только через реестр.** Перед упоминанием сотрудника PP в Vault-документах сначала проверять написание, актуальный статус, РГ / отдел, роль и грейд по `Рабочему реестру сотрудников PP` и профилям сотрудников, включая поиск по созвучию / фрагментам имени и фамилии. Старые транскрипты, проектные встречи, ФОТ-слой, письма, календарь и исторические артефакты не подтверждают актуальное участие человека сами по себе. Если человек выбыл, завершает работу, paused или не active, его можно фиксировать только как исторический след / источник / участника прошлого этапа, но нельзя включать в текущую команду, owner'ов, staffing, РГ-профиль или проектную ответственность без нового подтверждения. При обработке встреч и Notion-выжимек нельзя назначать человека владельцем задачи, digital-контура, продукта или рабочей роли только потому, что имя звучит тематически похоже: сначала сверить реестр и профиль, затем либо указать подтверждённую роль, либо писать `нужен владелец / уточнить в реестре сотрудников`. В тексте ставить wikilink на карточку сотрудника с alias для падежа: `[[Канон|форма в тексте]]`. Если сотрудник не найден в реестре, не придумывать имя и владельца, а писать `уточнить в реестре сотрудников`.
<!-- agents-norm:С-153:end -->

### С-163. Стандарт официальных инструкций и нормативных PDF

<!-- agents-norm:С-163:start -->
- Официальный документ пишется по-русски. Английские рабочие термины, названия метрик, этапов, проверок, ролей и формул заменяются точными русскими эквивалентами во всём документе, включая таблицы, подписи, формулы и колонтитулы. Допустимы только зарегистрированные собственные названия компаний, продуктов и информационных систем. После массовой замены обязателен поиск остаточной латиницы и полурусских гибридов с ручной проверкой падежей и смысла.
<!-- agents-norm:С-163:end -->

Служебные функции и обозначения вроде `floor()`, `B(E)` и нерасшифрованных латинских переменных в версии для сотрудника запрещены.
