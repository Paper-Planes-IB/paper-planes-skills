# MD Instruction Workflow

Use this workflow when a Paper Planes artifact needs a reusable project instruction, template instruction, or local operating rule.

## When To Create Or Update

Create or update an MD instruction only when the user explicitly confirms that the rule should be reusable.

Do not create an MD instruction just because a single artifact needs structure. For one-off work, keep the methodology choice in the response or artifact brief.

## Preflight

Before creating or updating an instruction:

1. Name the project or artifact family.
2. State the intended reuse case.
3. List the selected methodologies.
4. State whether MECE is required.
5. Name the canonical sources: Frappe knowledge base, local `instructions/`, approved client/project artifacts, and direct user instruction.
6. Identify what was live-verified in Frappe and what remains provisional.
7. Ask for explicit confirmation before writing.

## File Placement

When working inside a project folder, prefer a local `instructions/` folder.

When no project folder is available, do not invent a final storage location. Keep the instruction as a draft or ask where it belongs.

## Instruction Structure

Recommended sections:

- Purpose
- Applies When
- Inputs
- Canonical Sources
- Methodology Stack
- Workflow
- Output Contract
- Quality Gates
- Writeback / Approval Rules
- Known Gaps

## Quality Gates

Before marking an MD instruction ready:

- Check that source hierarchy is explicit.
- Check that methodology detail points to Frappe, not Notion or memory.
- Check that MECE is mandatory where structures, tables, categories, or diagrams are involved.
- Check that writeback requires explicit user approval.
- Check that unverified Frappe items are marked as not live-verified.
