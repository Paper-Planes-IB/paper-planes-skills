| Параметр | Описание |
|----------|----------|
| `text` | Текст |
| `bold` | Жирный |
| `size` | Размер (10-12) |
| `bullet` | Буллет (•) |
| `coral` | Выделить коралловым |
| `space_before` | Отступ сверху (pt) |

## Стиль Paper Planes

### Шрифт
- **Arial** — основной шрифт (доступен в PowerPoint по умолчанию)
- Размеры: 20-22pt заголовки, 11-12pt подзаголовки, 9-10pt контент

### Цвета

| Элемент | HEX |
|---------|-----|
| Фон | #FFFFFF |
| Текст | #000000 |
| Акцент | #FF5850 |
| Серый тёмный | #374151 |
| Серый средний | #6B7280 |
| Зелёный (RAG) | #22C55E |
| Жёлтый (RAG) | #EAB308 |
| Красный (RAG) | #EF4444 |

### Плотность контента
- Минимальные отступы (0.3") для максимального заполнения
- Текст должен быть развёрнутым, с конкретными цифрами
- Избегать пустых пространств — слайд должен быть насыщенным

## Передача в производство

Этот справочник описывает выбор конструкции, а не генератор. В установленном пакете нет рабочего `src.generator`; не запускай старые команды и не создавай конфиг ради отсутствующего инструмента. По умолчанию и при продолжении PDF-деки передавай согласованную композицию в `pp-slidument` для выпуска напрямую в PDF. Редактируемый PPTX или Slides — только по прямому запросу и после проверки допустимого маршрута.

## Workflow для Claude

1. **Storyboard** — до передачи в производство зафиксировать последовательность, action title и тип данных каждого слайда в согласованном источнике. Проверить, что одни заголовки образуют связную историю; использовать уже принятый storyboard без повторного согласования
2. **Собрать данные** — факты, цифры, источники
3. **Выбрать тип слайда** — по характеру данных (см. каталог типов выше):
   - Аргументация → `scqa`
   - Сравнение опций → `comparison`, `table`
   - Тренды → `chart`, `waterfall`
   - KPI метрика → `data`
   - Позиционирование → `matrix`
   - Потоки → `sankey`
   - Конверсионные воронки → `funnel`
   - Структура → `treemap`
   - Трансформации AS IS → TO BE → `from_to`
   - Процессы → `mermaid`, `flow_blocks`, `chevron_process`
   - Стратегический анализ → `swot`
   - Комбинированные данные → `chart_table`, `multi_table`
   - Таблица + sidebar метрики → `table_sidebar`
   - RASCI/RACI ответственность → `rasci`
   - Roadmap по горизонтам → `roadmap_swimlane`
   - Этапы проекта → `stage_gate`
   - Do/Don't правила → `do_dont`
   - Кампании × периоды (светофор) → `segment_matrix`
   - KPI / Goals список → `goals_rows`
   - Brand / EVP пирамида → `brand_pyramid`
   - Механизм / инструмент → `mechanism_card`
   - Декомпозиция проблемы / дерево решений → `issue_tree`
   - Цитата / интервью / голос клиента → `quote`
   - Пирамида Минто (тезис → аргументы → доказательства) → `pyramid`
   - Титул → `title_dark` (⛔ divider ЗАПРЕЩЁН)
   - Executive summary → `exec_summary`
   - Следующие шаги → `next_steps`
3. **Сформулировать Action Titles** — вывод в заголовок
4. **Анти-ИИ редактура**:
   - Нет "эксперты считают" без источника
   - Нет абстракций "символизирует/отражает"
   - Термины на русском (SKU → товарная позиция)
5. **Подготовить спецификацию композиции** в согласованном источнике.
6. **Передать в `pp-slidument`** для выпуска в прямо запрошенном формате; PDF собирать напрямую без промежуточного PPTX.
