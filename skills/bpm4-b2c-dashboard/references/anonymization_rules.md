# Правила обезличивания B2C-данных

## Что удаляем

- ФИО;
- телефон;
- email;
- адрес до квартиры или дома;
- точная дата рождения;
- номер карты лояльности в исходном виде;
- комментарии операторов;
- свободные текстовые поля с персональными данными.

## Что заменяем

| Исходное поле | Замена |
|---|---|
| `customer_id` | `customer_id_hash` |
| `phone` | не передавать; можно использовать только для хэша до выгрузки |
| `email` | не передавать; можно использовать только для хэша до выгрузки |
| `name` | удалить |
| `birth_date` | `age_group` |
| `address` | `city_or_region` |
| `brand` | можно оставить, если бренд не раскрывает клиента; иначе `brand_masked` |
| `sku_name` | можно оставить категорию; чувствительные SKU маскировать |

## Хэширование

Рекомендуется:

- соль хранится у клиента;
- в аналитику передаётся только результат хэша;
- один и тот же человек получает один и тот же `customer_id_hash` во всех таблицах;
- хэш не должен позволять восстановить телефон или email.

## Минимизация

Передавать только поля, которые нужны для расчётов и фильтров дашборда.

Не передавать:

- переписки;
- клиентские заметки;
- персональные документы;
- точные координаты дома;
- поля, не используемые в модели.

## Проверка перед передачей

- В выгрузке нет ФИО, телефонов и email.
- В выгрузке нет точных адресов.
- `customer_id_hash` стабилен между таблицами.
- Возраст передан диапазоном.
- Партнёрские и внутренние операции размечены.
- Есть отдельный список полей, которые были удалены или агрегированы.
