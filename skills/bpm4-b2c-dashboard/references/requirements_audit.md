# Аудит исходного пакета

Исходный файл: `bpm4_abis_package_20260729_090238.zip`.

## Вывод

Исходный пакет частично закрывает требования к обычному B2C-дашборду. Он содержит методическую основу BPM-4, список типов графиков, блоки RFM, повторных покупок, retention, Retail-кластеризацию и отдельное правило про партнёрский реестр перед RFM.

Пакет не является готовым обезличенным B2C-пакетом. В нём нет контракта данных, готового словаря метрик, правил анонимизации, структуры витрин, критериев приёмки и примеров таблиц для запроса выгрузки.

## Что закрыто

| Требование | Статус | Комментарий |
|---|---:|---|
| Формула прибыли | Частично | Описана методически, без готовых расчётных полей. |
| KPI-скаляры | Частично | Есть перечень блоков и отраслей, но нет B2C-словаря метрик. |
| Динамика выручки и чеков | Частично | Есть типы графиков, нет правил расчёта. |
| Повторные покупки | Частично | Блок присутствует в реестре графиков. Нужны формулы: repeat rate, частота, дни между покупками. |
| RFM | Частично | Метод есть, но нет порогов, правил исключений и выходных таблиц. |
| Кластеризация базы | Частично | Для Retail описан K-Means по RFM-профилю. Нужны критерии запуска и интерпретация. |
| Когорты | Частично | Упомянуты, но не оформлены как обязательная B2C-витрина. |
| Разрезы товаров, брендов, категорий | Частично | Есть типы графиков, нужен контракт строк чека. |
| Партнёры и B2B в базе | Хорошо | Есть отдельное правило: сначала единый реестр партнёров, затем B2C-RFM. |
| Обезличивание | Не закрыто | Нет правил хэширования, удаления персональных полей и минимизации. |
| Acceptance checklist | Не закрыто | Нет проверок сверки выручки, чеков, клиентов, дублей и возвратов. |

## Что добавлено в новом пакете

- обезличенная структура B2C-дашборда;
- контракт данных по таблицам;
- словарь метрик;
- правила RFM, повторных покупок, когорт и кластеров;
- правила исключения партнёров и внутренних операций;
- правила анонимизации;
- чеклист приёмки.

## Риски исходного пакета при прямом использовании

1. Можно смешать конечных покупателей и партнёров в одном RFM.
2. Можно посчитать повторные покупки по чекам без нормального `customer_id`.
3. Можно сравнить выручку без учёта возвратов и внутренних операций.
4. Можно построить красивые графики, но не пройти сверку с бухгалтерскими или CRM-итогами.
5. Можно передать пакет с клиентскими названиями, ссылками и контекстом.
