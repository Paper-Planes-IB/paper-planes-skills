# BPV-03.6 Regional Partner Growth

## Назначение

Этот skill превращает региональный партнёрский рост в проверяемый BPV-контур:

```text
региональный потенциал -> Bitrix-дедупликация -> поиск кандидатов -> квалификация -> первый контакт -> CRM / партнёрская воронка
```

Он подходит для НЭП / ПГС / РЕКРО и похожих экспертных B2B-компаний, которые растут через партнёров без открытия офисов.

## Core Rules

- Используй только проверяемые источники для числового scoring; оценочные слова не заменяют число.
- Сначала проверяй существующую партнёрскую воронку в Bitrix / CRM.
- Пустая или недоступная воронка не означает, что партнёров нет. Это вопрос пользователю или `access_gap`.
- Партнёр-кандидат не попадает в top-list без подтверждённого охвата или узкого премиального доступа к ЛПР.
- Не создавай / не меняй CRM-записи без отдельного change set и акцепта.

## Region Score

Базовые критерии:

| Критерий | Смысл | Правило |
|---|---|---|
| Потенциал спроса | объём и динамика рынка | Росстат, ЕРЗ, региональные программы, инвестиции |
| Институциональная плотность | ТПП, СРО, ассоциации, влияние | считать структуры, членов, представительство |
| Профильный спрос | ОКН, реконструкция, редевелопмент, судебные / разрешительные конфликты | фиксировать источник каждого числа |
| Логистика | время от базовой точки | низкий вес, только cost modifier |
| Конкуренция | пять сил Портера | нельзя давать итог без прохода по всем силам или явного gap |

## Partner Categories

- юридические фирмы;
- архитектурные и проектные бюро;
- инженерные и экспертные компании;
- кадастровые инженеры и земельные консультанты;
- бизнес-клубы, ТПП, союзы строителей, девелоперские ассоциации;
- организаторы отраслевых мероприятий;
- локальные консалтинговые и GR-игроки.

## Eval

- хороший триггер: “оцени регион”, “найди партнёров”, “проверь партнёрскую воронку”;
- плохой триггер: обычный ABM по target accounts без региональной партнёрской модели — route to `abm-pursuit-loop`;
- writeback-risk: CRM / Bitrix mutation;
- DLP: партнёрские статусы, стратегия выхода, внутренние scoring assumptions — `client_sensitive`.
